# ATDD Agent Plugin 0.1.4

Clarifies requirements verification after a reported run created
`docs/atdd-context.md` with a default-path instruction without confirming
that the requirements source existed.

## Changes

- Resolve an explicitly supplied source first, then a concrete source saved
  in context, then the default `docs/user-stories.md`.
- Check the chosen path and read relevant requirements on every run.
- Mark missing or unverified requirements as pending in context.
- Help draft and save missing stories and acceptance criteria, read back
  the saved content, and update the actual path and status in context.
- Before writing executable tests, read the saved source to verify that
  the selected story, agreed criteria and scenarios are present.

Existing agreement checkpoints, test tools and alternative requirements
locations remain supported. No runtime dependencies are added.

## Validation and limits

Skill structure, manifest consistency, local documentation links and strict
Claude packaging validation were checked. These checks do not establish
live model adherence. The revised instructions have not yet been exercised
in live Claude Code or Codex sessions; the README distinguishes the earlier
maintainer-reported client checks from this update.

## Update

Claude Code:

```sh
claude plugin marketplace update atdd
claude plugin update atdd@atdd
```

Codex CLI:

```sh
codex plugin marketplace upgrade atdd
codex plugin remove atdd@atdd
codex plugin add atdd@atdd
```

Start a fresh session after updating and confirm the installed plugin version
is `0.1.4`. See the README for first-time installation and invocation.
